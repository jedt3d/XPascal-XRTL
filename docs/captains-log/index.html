2026-06-12 05:30-05:42 ICT - Windows Toolchain Lessons

The Windows FPC 3.3.1 snapshot did not behave like a normal installed fpc.exe. The archive exposed a compiler named ppcrossx64.exe. The initial build created extensionless output files, which is confusing on Windows and can collide with command resolution if someone runs bare xpc.

Fixes applied:

  • Scripts discover both fpc.exe and ppc*.exe.
  • tools/build-xpc.ps1 renames Windows build outputs to xpc.exe and hello_xpc.exe.
  • tools/run-xpc.ps1 provides an unambiguous launcher.
  • The launcher sets FPC_BIN and FPC_VERSION.

Windows validation passed: install, toolchain check, build, xpc version, xpc doctor, and hello_xpc.

2026-06-12 05:57-06:08 ICT - macOS Apple Silicon Lessons

The Mac test machine was reached over SSH using local-only credentials. It reported macOS 26.5.1, Darwin arm64, on an Apple Silicon M2 system. This confirmed the required profile is macos-aarch64.

Findings:

  • The snapshot's bin/fpc driver is arm64 but fails because it cannot execute ppca64 from its expected path.
  • The real compiler is lib/fpc/3.3.1/ppca64, and it reports version 3.3.1.
  • Calling ppca64 directly requires explicit unit paths, otherwise system cannot be found.
  • macOS linking requires SDK flags: -syslibroot and -lSystem.
  • The first xpc doctor implementation spawned /bin/sh through Pascal runtime APIs and crashed on macOS, so bootstrap verification moved to shell launchers that pass FPC_VERSION into the CLI.

macOS Apple Silicon validation passed after these fixes: install, toolchain check, build, xpc version, xpc doctor, and hello_xpc.

2026-06-12 09:38 ICT - XRTL.Core Design Gate Opens

2026-06-12 09:55 ICT - FPC Release-Note Sweep Refines XRTL.Core

Revisited XRTL.Core after review feedback that compiler research should start from FreePascal release announcements and release-candidate notes, not from source-code guessing or stale wiki summaries. The useful release evidence is that official stable FreePascal remains 3.2.2, FPC 3.2.4-rc1 is a 2025 fixes-branch release candidate, and project-required 3.3.1 remains a development snapshot that must be validated directly on supported platforms.

The design now chooses a conservative modern style: flat unit name xrtl_core, ObjFPC advanced records for value-like primitives, simple generics only if they pass Windows x86_64, macOS Apple Silicon aarch64, and Ubuntu 26.04 x86_64, and no anonymous-function or function-reference APIs in Core v0. ADR 0006 moved from proposed to accepted for the follow-up implementation issue.
