XRTL.Text

Status: planned. No implementation exists yet.

Purpose

Text owns encoding, line-ending, escaping, and formatting helpers that are shared across Config, Diagnostics, Data, HTTP, and Web.

Responsibilities

  • UTF-8 policy and conversion boundaries.
  • Line ending normalization for generated files and tests.
  • Simple escaping helpers for diagnostics, config, HTTP headers, and docs examples.
  • String comparison policy where platform differences matter.

Non-Responsibilities

  • No full JSON implementation in the first plan; JSON should be a separate issue because mORMot and other libraries may already solve it well.
  • No HTML templating engine.
  • No database-specific escaping.

Dependencies

Text may depend on Core and Collections. It must not depend on Database, HTTP, or Web.

Refactor Check

Any library that handles UTF-8, line endings, or escaping must check Text first. This is especially important for generated projects, HTTP headers, SQL diagnostics, and config files.

First Tests

  • UTF-8 round-trip tests.
  • Line ending normalization tests for Windows and POSIX inputs.
  • Escaping tests for empty, ASCII, and non-ASCII content once Unicode fixtures are allowed.
