XRTL.Collections

Status: planned. No implementation exists yet.

Purpose

Collections owns reusable collection and iteration helpers only where FPC standard facilities are not enough for XRTL public contracts.

Responsibilities

  • Stable map/set/list contracts if FPC generics are not suitable for the supported compiler snapshot.
  • Small iteration helpers used by Data, HTTP headers, Config layers, or Diagnostics attributes.
  • Deterministic ordering helpers for tests and documentation examples.

Non-Responsibilities

  • No broad replacement of FPC containers for novelty.
  • No JSON, database row, or HTTP header domain logic.
  • No custom memory manager.

Dependencies

Collections may depend on Core. It should avoid depending on higher-level libraries.

Refactor Check

When another library needs a collection helper, prefer moving a generic helper here instead of copying local list/map code. If a helper is domain-specific, keep it in the domain library and document why.

First Tests

  • Deterministic ordering tests.
  • Empty and boundary collection tests.
  • Compile smoke with FPC 3.3.1 on all supported platforms.
