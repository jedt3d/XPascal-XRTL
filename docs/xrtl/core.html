XRTL.Core

Status: planned. No implementation exists yet.

Purpose

Core owns the smallest shared runtime primitives that other XRTL libraries need to communicate without depending on each other.

Responsibilities

  • Result status and error records.
  • Option/null value shape where FPC defaults are not sufficient for public APIs.
  • Feature flags and capability markers.
  • Small cross-library constants that do not belong to a domain library.

Non-Responsibilities

  • No logging implementation; use Diagnostics.
  • No text encoding helpers; use Text.
  • No file, process, network, or database access.

Dependencies

Core must not depend on other XRTL libraries. It may use FPC RTL features only when they are stable across supported platforms.

Refactor Check

Any new XRTL library that wants its own status, error, optional value, or capability type must first check whether Core should own it. Duplicating those shapes creates incompatible contracts and should require an ADR.

First Tests

  • Compile smoke for the Core unit.
  • Unit tests for result success/failure, error identity, and optional value behavior.
