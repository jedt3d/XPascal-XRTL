XRTL.Diagnostics

Status: planned. No implementation exists yet.

Purpose

Diagnostics owns structured runtime reporting: logs, diagnostic scopes, trace ids, and actionable failure messages.

Responsibilities

  • Diagnostic event shape and severity levels.
  • Trace id and scope propagation for CLI, build, database, HTTP, and Web flows.
  • Human-readable failure notes that can be surfaced by xpc doctor or test runners.
  • Pluggable sinks such as console, memory capture for tests, and later file output.

Non-Responsibilities

  • No config parsing; Config declares and reads settings.
  • No telemetry transport or cloud service integration in the first version.
  • No direct database or HTTP dependency.

Dependencies

Diagnostics may depend on Core, Time, and Text. It must remain usable by all other XRTL libraries.

Refactor Check

Any library that writes directly to stdout/stderr for runtime status should be reviewed. CLI launchers may print user-facing messages, but reusable XRTL units should emit diagnostics instead.

First Tests

  • Memory sink captures event order and severity.
  • Diagnostic scopes include nested context without leaking global state.
  • Failure messages stay stable enough for smoke assertions.
