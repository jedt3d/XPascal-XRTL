XRTL.Config

Status: planned. No implementation exists yet.

Purpose

Config owns typed configuration loading and precedence so libraries do not parse environment variables, local files, or defaults independently.

Responsibilities

  • Configuration key declaration and validation.
  • Layered sources: defaults, files, environment variables, and command-line overrides when needed.
  • Typed values for booleans, numbers, paths, durations, and connection settings.
  • Redaction policy for secrets in diagnostic output.

Non-Responsibilities

  • No ownership of process environment discovery; Process provides OS access where needed.
  • No database connection implementation; Database consumes config records.
  • No web route configuration beyond generic typed settings.

Dependencies

Config may depend on Core, Diagnostics, Text, IO, Process, and Time. It must not depend on Database, HTTP, or Web.

Refactor Check

If a library needs a setting, it should declare a Config key or record instead of reading environment variables directly. Any direct env access must be justified as bootstrap-only code.

First Tests

  • Precedence tests for default, file, environment, and override values.
  • Type parsing and validation failure tests.
  • Secret redaction tests.
