XRTL.Database

Status: planned. Issue #28 research recommends an XRTL-owned API with a first prototype adapter over FPC SQLDB.

Read the database/web candidate research.

Purpose

Database owns SQL and database adapter behavior while keeping public contracts independent from any single driver stack.

Responsibilities

  • Connection and transaction contracts built on XRTL.Data values.
  • Adapter boundary for PostgreSQL, MySQL/MariaDB, SQLite, and Firebird.
  • Driver capability detection and diagnostic reporting.
  • Future migration/query helper surface only after a separate issue defines it.

Non-Responsibilities

  • No generic row/field/value contracts; Data owns those.
  • No web request lifecycle or route handling.
  • No ORM in the first implementation slice.

Initial Candidate Posture

Candidate Current Posture Why
FPC SQLDB Recommended first prototype backend behind an XRTL wrapper. Built into the FPC ecosystem, provides a uniform SQL access layer, and includes SQLite, PostgreSQL, MySQL, and Firebird/InterBase connection units in upstream docs.
ZeosLib Deferred fallback/future adapter candidate. Broad database support, but license metadata includes LGPL-2.1 plus a separate Zeos-specific license file on the GitHub mirror. Use only if SQLDB gaps justify another provider.
mORMot 2 Deferred candidate for larger server/data stack. Very broad features and active modern Object Pascal scope. Risk is over-adopting a full framework when XRTL needs a narrow first database adapter.

Wrap Rationale

Database should wrap driver stacks behind XRTL.Data contracts because XPascal needs stable diagnostics, config, platform behavior, and test contracts even if the first backend changes. Directly exposing SQLDB, Zeos, or mORMot types would make later backend changes expensive.

Dependencies

Database may depend on Core, Diagnostics, Config, Data, Text, IO, Process, and Time. It must not depend on HTTP or Web.

First Tests

  • Driver-neutral connection config validation tests.
  • Data contract mapping tests without a live service.
  • SQLite local adapter smoke first through SQLDB.
  • PostgreSQL network smoke second.
  • Firebird and MySQL/MariaDB adapter tests only after service setup, native client libraries, and credentials are documented outside tracked files.
