XRTL.Database

Status: planned. No implementation exists yet.

Purpose

Database owns SQL and database adapter behavior while keeping public contracts independent from any single driver stack.

Responsibilities

  • Connection and transaction contracts built on XRTL.Data values.
  • Adapter boundary for PostgreSQL, MySQL/MariaDB, SQLite, and Firebird.
  • Driver capability detection and diagnostic reporting.
  • Future migration/query helper surface only after a separate issue defines it.

Non-Responsibilities

  • No generic row/field/value contracts; Data owns those.
  • No web request lifecycle or route handling.
  • No ORM in the first implementation slice.

Initial Candidate Posture

Candidate Current Posture Why
FPC SQLDB Preferred first prototype backend. Built into the FPC ecosystem, provides a uniform SQL access layer, and already names Firebird, PostgreSQL, and MySQL connection components in upstream docs.
ZeosLib Research-only candidate. Broad database support, but license metadata includes LGPL-2.1 plus a separate unknown Zeos license file on the GitHub mirror. Needs deeper license and maintenance review.
mORMot 2 Research-only candidate for larger server/data stack. Very broad features and active modern Object Pascal scope. Risk is over-adopting a full framework when XRTL may only need a narrow database adapter.

Wrap Rationale

Database should wrap driver stacks behind XRTL.Data contracts because XPascal needs stable diagnostics, config, platform behavior, and test contracts even if the first backend changes. Directly exposing SQLDB, Zeos, or mORMot types would make later backend changes expensive.

Dependencies

Database may depend on Core, Diagnostics, Config, Data, Text, IO, Process, and Time. It must not depend on HTTP or Web.

First Tests

  • Driver-neutral connection config validation tests.
  • Data contract mapping tests without a live service.
  • SQLite local adapter smoke first if SQLDB support is confirmed with FPC 3.3.1.
  • PostgreSQL, MySQL/MariaDB, and Firebird adapter tests only after service setup and credentials are documented outside tracked files.
