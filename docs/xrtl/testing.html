XRTL Test Strategy

XRTL tests should prove contracts, not only compile units. Every library must define its test surface before implementation merges.

Test Layers

Layer Purpose Default Location
Compile smoke Proves a unit or generated project can compile with FPC 3.3.1. tests/smoke/ and later tests/xrtl/<library>/
Unit tests Proves deterministic behavior of pure code: Core, Time, Text, Collections, Config parsing. tests/xrtl/<library>/
Contract tests Proves a shared abstraction behaves the same across adapters, platforms, and backends. tests/contracts/<capability>/
Adapter tests Proves Database, HTTP, or Web integrations against real or local service backends. tests/adapters/<adapter>/
Platform validation Proves supported platforms behave the same: Windows x86_64, macOS Apple Silicon, Ubuntu 26.04 x86_64. PR evidence and Captain's Log

Minimum Test Requirements By Library

Library First Required Tests
Core, Time, Text, Collections Pure unit tests plus compile smoke on all supported platforms.
Diagnostics, Config, IO, Process Unit tests plus platform-specific failure tests where OS behavior differs.
Data Contract tests for records, fields, parameters, result iteration, and error mapping.
Database Driver-neutral contract tests first; real PostgreSQL, MySQL, SQLite, and Firebird adapters only after service setup is explicit.
HTTP Request/response parsing tests, header/status tests, and loopback server/client smoke where supported.
Web Routing, middleware order, request context, error handling, and handler isolation tests.

Default Validation Command Shape

The exact commands will evolve as XRTL test runners exist. Until then, implementation PRs should extend the existing bootstrap pattern:

# Windows
./tools/check-toolchain.ps1
./tools/run-xpc.ps1 build
./tools/run-xpc.ps1 version
./tools/run-xpc.ps1 doctor

# macOS Apple Silicon / Ubuntu
bash ./tools/check-toolchain.sh
bash ./tools/run-xpc.sh build
bash ./tools/run-xpc.sh version
bash ./tools/run-xpc.sh doctor

Adapter Test Policy

  • Adapter tests must fail loudly when a required local service is intentionally enabled but unavailable.
  • Adapter tests must skip with a clear message when no service configuration is provided.
  • Credentials, hostnames, and service passwords stay in local ignored files or CI secrets, never in tracked docs.
  • Each adapter test must publish the tested backend version in PR evidence.

Definition Of Done For A Library PR

  1. The library document under docs/xrtl/ is current.
  2. Shared ownership was checked against XRTL Shared Architecture.
  3. Tests cover the first public behavior and at least one failure path.
  4. Any third-party dependency is registered in Dependency Provenance.
  5. Windows, macOS Apple Silicon, and Ubuntu validation expectations are recorded in the PR.
