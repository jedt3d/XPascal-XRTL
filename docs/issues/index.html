Issue Map

This page connects GitHub issues to the proposal, implementation evidence, validation, and close criteria. Issues are planning and accountability artifacts, not disposable notes.

Issue Rules

  • Every issue should name the proposal section or decision it implements.
  • Every issue should state scope, non-scope, acceptance criteria, implementation evidence, and validation status.
  • Issues remain open while PR #8 is draft/open, even if implementation has landed on the branch.
  • Close issues only after the PR is merged or after a maintainer marks the issue not planned.
