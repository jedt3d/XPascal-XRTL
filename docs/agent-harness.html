Agent Harness

This page is the operating checklist for Codex, GLM, and side-agent work in this repository.

Start Of Work

  • Fetch origin/main and start from an up-to-date local branch.
  • Confirm or create a GitHub issue before non-trivial work begins.
  • Create a feature branch named codex/<short-description>.
  • Keep the work scoped to the issue. Create follow-up issues instead of silently expanding scope.

Validation Hosts

Remote host credentials are local-only and must not be committed. Store them in .secrets/validation-hosts.local.md when needed; .secrets/ is ignored by Git.

  • Windows x86_64 validation runs locally and in GitHub Actions.
  • macOS validation targets Apple Silicon aarch64 only.
  • Linux validation targets Ubuntu 26.04 x86_64 first.

Validation Commands

Windows:

./tools/install-fpc.ps1
./tools/check-toolchain.ps1
./tools/run-xpc.ps1 build
./tools/run-xpc.ps1 version
./tools/run-xpc.ps1 doctor
./build/hello_xpc.exe

macOS Apple Silicon and Ubuntu:

bash ./tools/install-fpc.sh
bash ./tools/check-toolchain.sh
bash ./tools/run-xpc.sh build
bash ./tools/run-xpc.sh version
bash ./tools/run-xpc.sh doctor
./build/hello_xpc

Documentation Updates

  • Update Captain's Log when validation, merge state, support policy, or operating rules change.
  • Update Issue Map when issue status, scope, evidence, or close criteria change.
  • Update README and developer docs when commands or supported platform expectations change.
  • Update proposal source and generated HTML when the project plan changes.
  • Update the PRD when product scope, user workflow, public CLI behavior, platform support, or milestone priority changes.
  • Create or update ADRs when architecture, toolchain policy, runtime API shape, supported platforms, or repository governance changes.
  • For XRTL work, update docs/xrtl/architecture.html, docs/xrtl/testing.html, and the per-library page before implementation expands.
  • For open source candidates, update docs/dependencies.html before copying, vendoring, linking, or wrapping anything.

XRTL Pre-Implementation Gate

  • Check the linked GitHub issue and confirm whether it changes XRTL architecture, library boundaries, or dependency policy.
  • Read XRTL Shared Architecture and the target library document before editing runtime code.
  • Do not duplicate helpers across libraries. Shared status, errors, config, diagnostics, timeouts, paths, process execution, data rows, HTTP primitives, and Web routing each have an owner.
  • If a library needs a helper owned elsewhere, refactor toward the owner or open a follow-up issue. Do not silently create a second version.
  • Keep Database and Web candidates research-only until licensing, maintenance, platform, and test evidence is recorded.

PR Closeout

  • Run the validation plan from the linked issue.
  • Run git diff --check.
  • Search for stale status language and secrets before pushing.
  • Open a PR with Closes #<issue> when the issue should close at merge.
  • Wait for CI to pass and verify there are no unresolved review threads.
  • After merge, verify GitHub closed the intended issue and sync local main.
