Dependency Provenance Register

This register records third-party projects considered or adopted by XCLI and XRTL. No source should be copied, vendored, linked, or wrapped before license and provenance notes exist.

This document is an engineering register, not legal advice. Treat every license note as a prompt for verification against the exact upstream source and version before adoption.

Evaluation Rules

  • Prefer maintained projects with clear licenses and active upstreams.
  • Check cross-platform behavior for Windows x86_64, macOS Apple Silicon aarch64, and Ubuntu 26.04 x86_64.
  • Document attribution, copyright, and NOTICE obligations before adoption.
  • Record whether each project is adopted, wrapped, referenced, or only used as design inspiration.
  • When wrapping, document why a wrapper protects XPascal/XRTL better than direct use.

Minimal Express-inspired API, Lazarus/FPC quickstart, provider-neutral transport model, and FPC default fphttpserver provider are promising. XRTL.Web should still decide whether to wrap, adapt, or only borrow design ideas.
Web Brook GitHub repository LGPL-2.1 according to upstream README. Research-only candidate. Cross-platform Pascal microframework with rich server features. Needs activity, dependency, and license review before any adoption.
HTTP / Network Indy GitHub repository Dual-licensed under Indy Modified BSD or Indy MPL according to upstream README; exact license file compatibility must be reviewed. Research-only candidate. Broad protocol suite and recent release signal. Candidate for lower-level network/HTTP needs only if FPC integration and TLS dependency risks are acceptable.

Current Recommendations

  • Prototype XRTL.Database against FPC SQLDB first, but keep SQLDB behind XRTL.Data and XRTL.Database contracts.
  • Keep ZeosLib and mORMot 2 as research candidates until license, maintenance, platform, and API-shape evidence is stronger.
  • Prototype XRTL.HTTP loopback smoke with FPC fphttpserver if the FPC 3.3.1 snapshot includes the needed units on all supported platforms.
  • Treat Horse as a serious design/reference candidate for XRTL.Web, not a direct public API dependency yet.
  • Treat Brook and Indy as research candidates with explicit license and maintenance review before adoption.

Provenance Template

  • Project name and upstream URL
  • License and compatibility notes
  • Maintenance signal: recent releases, commits, issue activity, or maintainer status
  • Feature fit and missing capabilities
  • Cross-platform notes
  • Attribution and NOTICE obligations
  • Decision: adopt, wrap, reference, inspire only, reject, or defer
  • Rationale and linked issue/ADR
