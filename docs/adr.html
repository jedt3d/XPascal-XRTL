When To Create Or Update An ADR

  • Create an ADR when a change affects architecture, supported platforms, public CLI behavior, toolchain policy, repository workflow, or runtime API shape.
  • Update an existing ADR only when the original decision remains valid but needs clarified consequences or status.
  • Supersede an ADR with a new numbered record when the project reverses or materially changes a decision.
  • Reference the linked issue and PR when a decision is implemented.
  • Review ADR impact before merging platform, toolchain, CLI, runtime, or governance changes.
